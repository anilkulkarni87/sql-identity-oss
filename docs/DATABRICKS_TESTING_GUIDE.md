# Databricks Free Tier Testing & Walkthrough Guide

This comprehensive, step-by-step guide is designed for testing **SQL Identity Resolution (`v0.6.0`)** on **Databricks Free Tier** (Community Edition or 14-Day Free Cloud Trial).

It covers the complete journey:
1. **Data Ingestion**: Using datasets generated by [`Ecommerce_synthetic`](https://github.com/anilkulkarni87/ecommerce_synthetic) (or pure SQL generation).
2. **Web UI Walkthrough**: Connecting, configuring, and executing via the 6-Step Setup Wizard, Explorer, and Dashboard.
3. **Agentic MCP Tools**: Exercising `discover_and_suggest_rules`, `simulate_rule_impact`, and `resolve_customer_360`.
4. **Delta Lake Verification**: Inspecting final Golden Customer Profiles and cluster graphs in Databricks SQL.

---

## 📋 Prerequisites & Databricks Setup

### 1. Retrieve Your 3 Databricks Connection Parameters
From your Databricks workspace:
* **`DATABRICKS_HOST`**: The URL in your browser (e.g. `https://dbc-xxxx.cloud.databricks.com` or `https://community.cloud.databricks.com`).
* **`DATABRICKS_TOKEN`**: User profile icon (top-right) $\rightarrow$ **Settings** $\rightarrow$ **Developer** $\rightarrow$ **Access tokens** $\rightarrow$ **Generate new token**.
* **`DATABRICKS_HTTP_PATH`**:
  * For SQL Warehouse: **SQL Warehouses** $\rightarrow$ select your warehouse $\rightarrow$ **Connection details** $\rightarrow$ copy **HTTP path** (e.g. `/sql/1.0/warehouses/xxxx`).
  * For All-Purpose Cluster (Community Edition): **Compute** $\rightarrow$ select cluster $\rightarrow$ **Advanced options** $\rightarrow$ **JDBC/ODBC** $\rightarrow$ copy **HTTP path**.
* **`DATABRICKS_CATALOG`**:
  * For Community Edition: `hive_metastore`
  * For Unity Catalog: your catalog name (e.g. `main`)

3. Drop `customers.parquet`, `instore_accounts.parquet`, `loyalty_members.parquet`, and `orders_online.parquet`.
4. Click **Create Table** for each.

### 2. The 6-Step Setup Wizard Walkthrough (`/setup`)

1. **Step 1: Connect (`/setup/connect`)**
   * Platform: Select **Databricks**.
   * Enter your `DATABRICKS_HOST`, `DATABRICKS_HTTP_PATH`, `DATABRICKS_TOKEN`, and `Catalog` (`hive_metastore` or `main`).
   * Click **Test Connection** $\rightarrow$ shows a green "Connected" badge.
2. **Step 2: Discover (`/setup/discover`)**
   * Select your schema: `ecommerce_demo`.
   * Click on `customers`, `instore_accounts`, and `loyalty_members` to preview column names and data types.
3. **Step 3: Map Identifiers & Attributes (`/setup/map`)**
   * `customers`:
     * Entity Key: `customer_id`
     * Identifiers: `email` $\rightarrow$ `EMAIL`, `phone` $\rightarrow$ `PHONE`
     * Attributes: `first_name`, `last_name`
   * `instore_accounts`:
     * Entity Key: `instore_account_id`
     * Identifiers: `phone_number` $\rightarrow$ `PHONE`
     * Attributes: `customer_name`
   * `loyalty_members`:
     * Entity Key: `loyalty_id`
     * Identifiers: `account_email` $\rightarrow$ `EMAIL`
     * Attributes: `tier`
4. **Step 4: Rules (`/setup/rules`)**
   * Add Rule 1: Match Key `email`, Type `EXACT`, Priority `1`, `max_group_size = 50`.
   * Add Rule 2: Match Key `phone`, Type `EXACT`, Priority `2`, `max_group_size = 25`.
   * *(Optional)*: Add Fuzzy Rule on `first_name` using Jaro-Winkler similarity.
5. **Step 5: Survivorship (`/setup/survivorship`)**
   * `first_name`: `SOURCE_PRIORITY` (`customers`, `instore_accounts`)
   * `email`: `RECENCY`
   * `tier`: `RECENCY`
6. **Step 6: Review & Run (`/setup/review`)**
   * Click **Dry Run Preview** $\rightarrow$ see the exact impact scorecard:
     * `New Entities`: 7
     * `Moved Clusters`: 0
     * `Unchanged`: 0
   * Click **Run Pipeline** $\rightarrow$ watch the live stage-by-stage execution (`extraction` $\rightarrow$ `graph` $\rightarrow$ `cluster` $\rightarrow$ `metrics` $\rightarrow$ `output`).

## 🤖 Part 4: Testing the New Agentic MCP Tools

The new agentic tools in `v0.6.0` allow AI assistants (Cursor, Claude, or Python scripts) to autonomously profile schemas, simulate rule risks, and retrieve single-call Customer 360 context.

### 1. Set Environment Variables
```bash
export IDR_PLATFORM=databricks
export DATABRICKS_HOST="https://your-databricks-instance.cloud.databricks.com"
export DATABRICKS_TOKEN="dapi_your_token_here"
export DATABRICKS_HTTP_PATH="/sql/1.0/warehouses/your_warehouse_id"
export DATABRICKS_CATALOG="hive_metastore" # or "main"
export IDR_PII_ACCESS="full"               # unmasked output
```

### 2. Interactive Python Script
Run the following script to exercise all 3 agentic tools on your Databricks tables:

```python
import json
from idr_mcp import server as mcp

mcp.connect_from_env()

print("=" * 80)
print("1. Testing discover_and_suggest_rules()")
print("=" * 80)

# Autonomous table profiling & PII discovery
discovery = mcp.discover_and_suggest_rules()

print(f"Tables Profiled:      {discovery.get('tables_profiled')}")
print(f"Detected Identifiers: {discovery.get('detected_identifiers')}")
print(f"Detected Attributes:  {discovery.get('detected_attributes')}")
print("\nSuggested Declarative Rules:")
print(json.dumps(discovery["suggested_config"]["rules"], indent=2))


print("\n" + "=" * 80)
print("2. Testing simulate_rule_impact() on Candidate Rules")
print("=" * 80)

# Simulate candidate rule with max_group_size = 2
candidate_rule = {
    "id": "exact_phone",
    "type": "EXACT",
    "match_keys": ["phone"],
    "max_group_size": 2
}
simulation = mcp.simulate_rule_impact(candidate_rule)

print(f"Rule ID:                 {simulation.get('rule_id')}")
print(f"Eligible Entities:       {simulation.get('eligible_entities')}")
print(f"Simulated Anchor Edges:  {simulation.get('simulated_anchor_edges')}")
print(f"Supernode Groups Alert:  {simulation.get('supernodes_flagged')}")
print(f"Risk Level:              {simulation.get('risk_level')}")
print(f"Risk Reasons:            {simulation.get('risk_reasons')}")


print("\n" + "=" * 80)
print("3. Testing resolve_customer_360() Single-Call Context Grounding")
print("=" * 80)

# Resolve Alice using her phone number
c360 = mcp.resolve_customer_360("555-0101")

print(f"Found:            {c360.get('found')}")
print(f"Resolved ID:      {c360.get('resolved_id')}")
print(f"Cluster Size:     {c360.get('cluster_size')} linked accounts")
print(f"Confidence Score: {c360.get('confidence_score')}")

print("\nGolden Master Profile:")
print(json.dumps(c360.get("golden_profile"), indent=2))

print("\nLinked Source Accounts:")
for acc in c360.get("linked_accounts", []):
    print(f"  • System: {acc['source_system']:<20} Entity: {acc['entity_key']}")

print("\nAll Known Cross-Channel Identifiers:")
for idn in c360.get("known_identifiers", []):
    print(f"  • [{idn['type'].upper()}]: {idn['value']}")
```

## 🔍 Part 5: Inspect Results Directly in Databricks SQL

In your **Databricks SQL Worksheet**, run these validation queries against the Delta Lake serving tables:

```sql
-- 1. View Golden Master Customer Profiles
SELECT * FROM idr_out.golden_customer_profiles;

-- 2. View Cluster Memberships across CRM, POS, and Loyalty
SELECT 
    m.entity_key,
    m.resolved_id,
    c.cluster_size,
    c.confidence_score
FROM idr_out.identity_resolved_membership_current m
JOIN idr_out.identity_clusters_current c ON m.resolved_id = c.resolved_id
ORDER BY c.cluster_size DESC, m.resolved_id;

-- 3. View Skipped High-Cardinality Groups (Auditing protection against shared_support@example.com)
SELECT * FROM idr_out.skipped_identifier_groups;

-- 4. View Stage Metrics Telemetry
SELECT 
    stage_name, 
    records_in, 
    records_out, 
    duration_ms 
FROM idr_out.stage_metrics
ORDER BY started_at DESC;
```

## 💡 Troubleshooting Databricks Free Tier Gotchas

1. **Auto-Terminating Cluster / Compute Cold Start**:
   * Free Tier compute terminates after 20 minutes of inactivity. If a query or CLI command times out with `Connection refused` or `503 Service Unavailable`, open your Databricks workspace and ensure the cluster or SQL warehouse is running.
2. **Delta Column Defaults**:
   * Databricks Delta Lake requires enabling column defaults explicitly on some clusters. IDR automatically suppresses invalid default clauses in DDL so table creation succeeds out of the box.
3. **Unity Catalog vs Hive Metastore**:
   * If using Unity Catalog, tables are accessed as `catalog.schema.table`. Ensure `DATABRICKS_CATALOG` matches your catalog name (default is `hive_metastore` for Community Edition).
